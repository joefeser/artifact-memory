# Artifact Memory 0.1.3 release notes

Artifact Memory 0.1.3 is a query-integrity and retrieval update over v0.1.2.
It adds integrity-gated SQLite projection reads, digest-bearing search
receipts, literal search, optional lifecycle filtering, and optional
non-authoritative BM25 ranking.

Release status is established only by an owner-signed annotated `v0.1.3` tag
and its verified release-manifest binding. This reviewed source document does
not claim that signing, publication, or attestation has occurred.

## Projection integrity and schema identity

- Every public projection reader validates the exact generated application
  object set, ordinary table and explicit-index declarations, canonical rows,
  source-record-set digest, FTS5 declaration, and physical integrity inside
  one read transaction.
- Complete declaration validation rejects substitutions that preserve column
  names while changing primary keys, foreign keys, checks, or collations. This
  prevents case-insensitive identity joins from producing falsely verified
  lifecycle-filtered results.
- A cached behavioral probe must demonstrate that the loaded SQLite/FTS5 build
  detects a known inverted-index forgery. A version number alone does not
  establish that capability for a custom build.
- Generated projections remain disposable. These gates do not establish the
  authenticity or truth of canonical records.

## Search receipts and query modes

- The additive `search-receipt` library and CLI surfaces bind matched record
  IDs and every active result-shaping mode to the exact source record set.
- Receipts retain a SHA-256 digest of the exact UTF-8 query bytes rather than
  the raw query. The unkeyed digest can still reveal guessable low-entropy
  input through offline dictionary inference.
- Optional literal mode quotes FTS5 syntax and applies the documented
  case-folded substring condition. It is not general Unicode substring search.
- Query and projection failures remain distinct typed outcomes.

## Lifecycle filtering and ranking

- `--exclude-superseded` is additive and off by default. When selected, both
  raw and literal searches apply a candidate-bounded lifecycle join whose
  schema semantics are verified before use. This is result shaping, not
  revocation, deletion, or a current-truth decision.
- `--rank` is additive and off by default. It uses explicit `bm25(records_fts)`
  with a deterministic record-ID tiebreak.
- Ranked receipts label order as informational, non-authoritative, and
  corpus-dependent. A heterogeneous synthetic probe demonstrates a rank flip
  at both 1,000 and 5,000 records after adding a document that contains neither
  query term while leaving the matched set unchanged.

## Runtime and evidence boundary

Upstream SQLite added virtual-table `xIntegrity` coverage in 3.44. The runtime
nevertheless performs a behavioral capability probe and fails closed with
`projection-unavailable` when the loaded FTS5 implementation cannot detect the
known forgery. Check the Python-linked engine with:

```shell
python3 -c 'import sqlite3; print(sqlite3.sqlite_version)'
```

The cross-runtime evidence distinguishes standalone engine probes from Python
library execution. Python-linked 3.46.1 and 3.52.0 provided the measured
gate-passing library evidence. Standalone CLI evidence, including 3.51.0, does
not establish Python-library or cross-platform behavior. The general macOS,
Linux, and Windows platform workflow does not independently prove this query
matrix.

## Compatibility

- Published v0.1.0-v0.1.2 canonical and protocol schemas retain their original
  meanings. Existing default search output shapes remain unchanged.
- Search receipts and flags are additive. No context-pack, exchange, deletion,
  tombstone, adapter, or custody schema changes in this release.
- Physically inconsistent projections, schema-substituted projections, and
  clean projections on incapable SQLite/FTS5 builds now fail closed. Rebuild
  generated projections from canonical text on a supported runtime.

## Authority and remaining limitations

Search, ranking, lifecycle filters, integrity receipts, and generated views are
informational. They create no execution, mutation, disclosure, routing,
credential, spending, deployment, approval, declassification, or merge
authority. Integrity verification detects the bounded supplied projection; it
does not prevent denial of service, enumerate unknown copies, or prove source
authenticity. Per-query validation cost remains proportional to the projection
corpus and BM25 order remains corpus-dependent.
