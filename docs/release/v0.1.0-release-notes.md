# Artifact Memory 0.1.0 release notes

Artifact Memory 0.1.0 is the first public source release of a filesystem-first,
contract-first system for durable knowledge and artifact memory across people,
agents, machines, and storage providers.

Release status is established only by the dedicated owner-signed annotated
`v0.1.0` tag and its verified release-manifest binding. This document is the
reviewed release body in the source tree; its presence alone does not claim
that signing or publication has occurred.

## Included product proof

- Versioned canonical records preserve provenance, revision identity,
  supersession, disputes, and contradictions without making generated indexes
  authoritative.
- Exact byte and normalized-tree identities remain distinct from artifact,
  version, semantic, and location identities.
- Portable resolvers and explicit scan-completeness outcomes avoid treating a
  hostname, path, mount point, drive letter, or provider URL as durable
  identity.
- NDJSON, SQLite, and context projections rebuild from canonical records.
- Bounded context packs expose selection provenance and budget decisions while
  carrying no execution, routing, disclosure, spending, deployment, or merge
  authority.
- Exchange admission, revocation, tombstone, retention, and deletion receipts
  preserve recipient and endpoint outcomes without claiming global erasure.
- Synthetic TraceMap and WITS adapter fixtures preserve provider ownership:
  TraceMap owns static-analysis evidence, while WITS owns meaning, decisions,
  readiness, routing, authority, and conflict resolution.
- Authorized Codex-history ingestion curates vendor-neutral records without
  publishing raw task transcripts.
- Encrypted off-machine custody, integrity checking, and isolated restoration
  were dogfooded privately and represented publicly only by sanitized evidence.

Compatibility correction (2026-08-11): the WITS ownership wording above is
superseded by Decision 0020. The authorized human originates product meaning;
WITS authenticates authority, admits human decisions, and governs their
recorded lifecycle. The released `owner-meaning` identifier remains frozen for
wire compatibility only.

## Trust and authority boundaries

Integrity is not authenticity. Authenticity is not trust. A valid record,
verified digest, signed exchange, context pack, adapter payload, or recovered
backup never grants authority to execute, mutate, disclose, route, spend,
deploy, declassify, or merge. HACP Task Packets and WITS route authority remain
separate authority-bearing contracts.

Artifact Memory does not import TraceMap or WITS provider schemas into its core
contracts, reinterpret provider evidence, or treat TraceMap provenance as an
authenticity claim.

## Compatibility

The protocol, schemas, reference CLI, adapters, and fixtures have independent
version boundaries. Unknown optional extensions are preserved without
interpretation; unknown required extensions fail closed. Before 1.0, Python
implementation APIs may change, but published versioned contracts are not
silently reinterpreted. Deprecation follows the window documented in
`docs/release/versioning-and-launch.md`.

## Known limitations

- Artifact Memory is a local reference implementation, not a hosted service,
  credential vault, generalized execution runtime, mutable file synchronizer,
  or plugin marketplace.
- Semantic retrieval is optional and is not required for deterministic recall;
  the release does not claim a hosted embedding or vector-search service.
- Filesystem completeness and TraceMap analysis completeness remain separate
  facts, and difficult filesystem semantics may produce explicit unsupported
  or collision outcomes.
- Revocation and deletion propagate bounded receipts and suppression behavior;
  they cannot prove global erasure across uncontrolled recipients or immutable
  historical audit media.
- Keyless build and artifact attestations remain deferred until public workflow
  review supports them.
- Private vault contents, resolver configuration, credentials, raw task
  histories, and recovery material are intentionally absent from the public
  repository and release assets.

## Verification

Release assets include a deterministic source archive, these exact release
notes, `SHA256SUMS`, and a v2 pending release-candidate manifest. The manifest digest is bound by
the owner-signed annotated tag. Verification also replays the exact staged
archive and release notes against the tagged source and canonical checksum
scope. Follow
`docs/release/versioning-and-launch.md` and
`docs/release/public-readiness-audit.md` to verify checksums, the public SSH
Ed25519 signing fingerprint, exact commit and package identity, and an isolated
anonymous clone/install smoke.

## Lineage

Artifact Memory is an Apache-2.0 clean rewrite informed by Joe Feser's 2010
WhereAreMyFiles project. Historical lineage and the non-migration boundary for
legacy SHA-1 and `NONE` values are documented in
`docs/contracts/v0-lineage-observations.md`.
