# Artifact Memory 0.1.1 release notes

Artifact Memory 0.1.1 is a backward-compatible correctness and conformance
release over the first public source release. It strengthens candidate
admission, lifecycle-aware context export, and release verification without
granting new authority or silently changing any released v0.1.0 schema.

Release status is established only by the dedicated owner-signed annotated
`v0.1.1` tag and its verified release-manifest binding. This document is the
reviewed release body in the source tree; its presence alone does not claim
that signing or publication has occurred.

## Correctness and conformance repairs

- Release asset replay now distinguishes a byte mismatch from an independent
  Git replay failure, preserving precise fail-closed diagnostics.
- `knowledge-candidate/v2` binds an explicit portable namespace, bounded input
  references, canonical source revisions, and first-class uncertainty without
  requiring a derivative claim.
- `candidate-admission-receipt/v2` proves accepted, rejected, disputed, stale,
  duplicate, unsupported, and conflicting outcomes while binding immutable
  predecessor transitions.
- A v2 supersession requires the exact predecessor record plus caller-supplied
  current-revision evidence. A retained historical accepted body is not enough
  to produce an accepted transition.
- `context-pack/v4` directly excludes draft, superseded, rejected, and other
  lifecycle-ineligible records before freshness evaluation. Its receipt keeps
  lifecycle exclusion separate from freshness and discloses no excluded record
  identities.
- Valid revocation acknowledgements for already lifecycle-ineligible revisions
  are checked but do not abort export or appear as applied revocation evidence.
- Corrected Codex-history conformance uses a lifecycle-aware v2 fixture while
  preserving every historical v1 schema and fixture byte.

## Release tooling

- Versioned v2 preview and release-candidate preparation receipts support
  subsequent `X.Y.Z` releases while keeping the v0.1.0 v1 receipt contracts
  frozen.
- Release IDs, tags, archive names, notes paths, package versions, manifests,
  and checksum assets are derived from and cross-bound to the exact committed
  semantic version.
- Candidate preparation still accepts only the public SSH signing fingerprint
  and key-generation label. It never accepts or invokes private key material.

## Compatibility

The v0.1.0 candidate, admission, context-pack v2/v3, release-preparation, and
release-candidate-preparation contracts remain readable and unchanged. New
behavior is negotiated through new schema identifiers; there is no silent
downgrade or reinterpretation. Unknown optional extensions remain preserved,
and unknown required extensions continue to fail closed.

## Trust and authority boundaries

Candidate admission records a caller-supplied decision; it does not authenticate
the authority behind human-originated meaning. Current-revision evidence is
checked for exact binding but does not prove that an integrating store supplied
an authenticated atomic snapshot.
Context packs, release receipts, verified digests, adapter evidence, and
recovered backups remain informational and grant no execution, routing,
disclosure, mutation, merge, deployment, spending, credential, or
declassification authority.

## Known limitations

- The current Codex-history runner emits the corrected v2 proof; the frozen v1
  fixture is archival compatibility evidence rather than an operational replay
  target.
- JSON Schema validation is structural. Canonical ordering, identity,
  cross-binding, and context recall semantics require the corresponding
  semantic validator or independent reader.
- Revocation and deletion remain bounded endpoint and recipient evidence; they
  do not prove global erasure.
- Keyless build and artifact attestations remain deferred pending a separately
  reviewed public workflow.

## Verification

Release assets contain a deterministic source archive, these exact notes,
canonical `SHA256SUMS`, and a v2 pending release-candidate manifest. The owner-
signed annotated tag binds the manifest digest. Verification replays every
staged asset against the tag, package version, source tree, manifest, and
checksum scope before publication.
